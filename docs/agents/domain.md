# Domain docs

## Layout

This repository uses a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decisions under docs/adr/.

## Before exploring

Read GLOSSARY.md when present, CONTEXT.md for existing domain
terminology and architecture, and ADRs relevant to the work.

If glossary files are absent, proceed without creating placeholders.
The domain-modeling skill can create them when terminology is resolved.

## Vocabulary and decisions

Use the project's established domain terms consistently.
Identify gaps when resolving new domain concepts.
Surface conflicts with existing ADRs explicitly rather than silently
overriding them.

Preserve dated historical decisions. Do not treat historical scheduler,
issue or deployment descriptions as evidence of current operation.
